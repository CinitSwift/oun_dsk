# 内置默认视频源设计

## 目标

为应用内置用户提供的 20 个视频源，并让新安装、已有安装和“恢复默认”场景获得可预期且不破坏用户配置的行为。

## 默认源定义

- 在视频源配置模块中维护一份内置默认源常量，共 20 项。
- 每项保留用户提供的 `id`、`name`、`url` 和 `isEnabled`。
- 复用现有解析逻辑补充 `detailUrl`、`updatedAt`、`timeout` 和 `retry`。
- 配置优先级保持不变：`VITE_INITIAL_CONFIG` 高于 `VITE_INITIAL_VIDEO_SOURCES`，内置默认源仅作为两者均未提供时的 fallback。

## 初始化与升级

- 新用户首次启动时加载全部内置默认源。
- 已有用户通过一个带版本号的本地初始化标记执行一次升级迁移。
- 升级迁移只追加当前不存在的默认源，不覆盖已有源的名称、URL、启用状态、超时、重试等用户配置。
- 去重沿用现有规则：相同 `id`，或相同 `name` 与 `url`，均视为已存在。
- 当前默认源版本迁移完成后不再重复执行，因此用户之后手动删除某个内置源时，后续启动保持删除状态。
- 后续若默认源列表再次调整，可提升默认源版本，触发下一次一次性迁移。

## 恢复默认

- “恢复默认”继续先清空当前视频源，再调用初始化逻辑。
- 恢复后加载当前配置优先级对应的完整默认源集合；未配置环境变量时即为这 20 个内置源。
- 恢复默认不依赖启动迁移标记。

## 错误与兼容性

- 远程 URL 的可用性不在启动时探测，避免某个源离线阻塞应用初始化。
- 保留 HTTP 源原值，不在配置层自动改写协议；实际访问继续走现有内置代理。
- 环境变量自定义默认源的现有行为不变。

## 验证

- 运行 TypeScript/Vite Web 生产构建。
- 运行桌面模式前端生产构建。
- 运行 ESLint，并如实记录仓库已有问题与本次新增问题。
- 检查最终差异，确认 20 个源的 ID、名称、URL、启用状态与用户输入一致。

## 非目标

- 不探测或保证第三方视频源长期可用。
- 不覆盖或重置已有用户的视频源配置。
- 不为现有视频源逻辑引入新的测试框架。
